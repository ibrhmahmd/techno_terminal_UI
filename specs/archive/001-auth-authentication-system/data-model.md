# Data Model: Auth Authentication System

## Entities

### User

Represents a person with access to the TechnoTerminal CRM system.

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `id` | `number` | Yes | Primary key, auto-generated by backend |
| `employee_id` | `number` | Yes | Links to employee record in HR system |
| `username` | `string` | Yes | Login username |
| `email` | `string` | Yes | Login identifier used in authentication form |
| `role` | `enum` | Yes | Access level: `admin`, `system_admin`, or `staff` |
| `is_active` | `boolean` | Yes | Whether the user account is active |
| `last_login` | `string` (ISO 8601) | Yes | Timestamp of most recent login |
| `created_at` | `string` (ISO 8601) | No | Timestamp of account creation |

**Role Hierarchy:**
- `system_admin` — full system access, can manage other admins
- `admin` — administrative access to most features
- `staff` — limited access to operational features (not yet enforced via RoleBasedRoute)

**Validation Rules:**
- email must be a valid email format (server-validated)
- role must be one of `admin`, `system_admin`, `staff` (server-validated)

### AuthTokens

Pair of JWT tokens returned by login and refresh endpoints.

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `access_token` | `string` (JWT) | Yes | Short-lived token (minutes/hours) for API authentication. Sent as `Bearer` header |
| `refresh_token` | `string` (JWT) | Yes | Long-lived token (days) for obtaining new access tokens. Sent to `/auth/refresh` |
| `token_type` | `string` | Yes | Always `bearer` |

**Storage:**
- Both tokens stored in localStorage via Zustand persist middleware (key: `auth-storage`)
- `access_token` injected into Axios request headers
- `refresh_token` only used for `/auth/refresh` calls

## API Request/Response Types

### Login

```
POST /auth/login
```

**Request:**
```typescript
interface LoginCredentials {
  email: string
  password: string
}
```

**Success Response:**
```typescript
interface LoginResponse {
  success: boolean
  data: {
    access_token: string
    refresh_token: string
    token_type: string
    user: User
  }
  message: string
}
```

### Refresh Token

```
POST /auth/refresh
```

**Request:**
```typescript
interface RefreshRequest {
  refresh_token: string
}
```

**Success Response:**
```typescript
// Same shape as LoginResponse — returns new token pair + user
```

### Logout

```
POST /auth/logout
```

**Request:** Empty body (auth via Bearer token)

**Response:** `void`

### Get Current User

```
GET /auth/me
```

**Response:**
```typescript
interface ApiResponse<T> {
  success: boolean
  data: T
  message: string
}
// T = User
```

### Create User (Admin)

```
POST /auth/users
```

**Request:**
```typescript
interface CreateUserRequest {
  employee_id: number
  username: string
  password: string
  role: 'admin' | 'system_admin'
}
```

**Response:** `User`

### Reset Password (Admin)

```
POST /auth/users/:id/reset-password
```

**Request:**
```typescript
interface ResetPasswordRequest {
  new_password: string
}
```

**Response:** `void`
